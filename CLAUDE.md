## Commands

Package manager is Yarn (`yarn.lock`). There is no lint, test, or formatter setup.

- `yarn start` — Expo dev server
- `yarn android` / `yarn ios` — `expo run:android|ios` (native build; see below)
- `yarn web` — Expo web
- `npx tsc --noEmit` — type-check (strict mode, extends `expo/tsconfig.base`)

The app is **not Expo Go compatible**: fonts are embedded natively through the `expo-font` config plugin and `react-native-image-picker` is a bare native module, so run it as a dev build. `/android` and `/ios` are generated by prebuild and gitignored — change native config in `app.json` (plugins), not in those folders.

## Architecture

React Native (Expo SDK 57, React 19, RN 0.86) client for a property-listing platform, backed by a separate PHP API. Entry: `index.ts` → `App.tsx`, which nests `I18nextProvider` → `SafeAreaProvider` → `AuthProvider` → `AppNavigator`. `App` renders nothing until `loadStoredLanguage()` resolves so the first screen is in the user's saved language.

- **Navigation** ([src/navigation/AppNavigator.tsx](src/navigation/AppNavigator.tsx)): native stack (`Main` tabs, `PropertyDetails`, `SignIn`, `SignUp`) wrapping a bottom-tab navigator. The `Dashboard` tab is only registered when `isAuthenticated`. Browsing is open to guests; sign-in is a modal-style stack screen, not a gate. All headers are hidden — each screen draws its own via `ScreenHeader`. Param lists (`RootStackParamList`, `MainTabParamList`) are exported from this file.
- **Auth** ([src/context/AuthContext.tsx](src/context/AuthContext.tsx)): `user` is hydrated from SecureStore (`user_data`) on launch; the bearer token lives in SecureStore under `auth_token`. `login`/`signup` return `{ success, error }` rather than throwing.
- **API** ([src/services/api.ts](src/services/api.ts)): a single axios instance whose request interceptor attaches `Bearer <auth_token>` from SecureStore, and whose 401 response interceptor clears the stored token/user (it does not update `AuthContext` state). Endpoints are `*.php` scripts (e.g. `/signin.php`, `/search_properties.php`), grouped into `authApi`, `propertyApi`, `contactApi`, `userApi`. `API_BASE_URL` is hardcoded to a LAN IP (`http://192.168.1.15/boninzu/api`) — update it to match your dev machine's address.
- **i18n** ([src/i18n/](src/i18n/)): English, French, Kinyarwanda (`en`/`fr`/`rw`). Device language is the default, English the fallback; the user's choice persists in SecureStore (`app_language`) via `setLanguage`. Every user-facing string goes through `useTranslation`/`i18n.t` — add new keys to **all three** locale files in [src/i18n/locales/](src/i18n/locales/).
- **Styling**: no UI library. Design tokens (`colors`, `radius`, `shadow`, `HIT` touch-target size) live in [src/theme.ts](src/theme.ts); shared primitives are in [src/components/](src/components/).
- **Typography gotcha** ([src/components/Typography.tsx](src/components/Typography.tsx)): on Android a custom font ignores `fontWeight`, so Poppins ships as four separate files. Import `Text`/`TextInput` from `Typography` (not `react-native`) — they map `fontWeight` to the right Poppins family — and use the exported `fonts` constants when setting `fontFamily` directly (e.g. tab bar labels).
- **Types** ([src/types/index.ts](src/types/index.ts)): `User`, `Property`, etc. mirror the PHP API's response shapes (snake_case fields).
